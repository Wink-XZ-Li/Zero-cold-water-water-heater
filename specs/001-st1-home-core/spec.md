# Feature Specification: ST1 Pro 首页核心能力

**Feature Branch**: `001-st1-home-core`

**Created**: 2026-08-12

**Status**: Draft

**Input**: 用户确认的 Grill 共识 — 伊莱克斯零冷水燃气热水器 ST1 Pro 面板首包：设备能力模型对齐 + 首页主控 + 零冷水入口占位二级页；设置定时与其余能力仅写入路线图。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 打开面板查看并控制热水主状态 (Priority: P1)

用户打开设备面板后，在首页看到热水器当前是否开启、工作模式、设定温度与出水温度、工作状态，并可完成开关、切换模式、调节设定温度。

**Why this priority**: 这是用户每次用水前的核心路径，构成首包 MVP。

**Independent Test**: 在虚拟设备或真机上模拟开关、模式、温度与工作状态变化，仅验证首页主控区即可交付可演示价值。

**Acceptance Scenarios**:

1. **Given** 设备在线且面板加载完成, **When** 用户打开首页, **Then** 显示电源开关状态、当前工作模式、设定温度、出水温度与工作状态（关机/待机/洗澡加热/零冷水加热等可读文案）
2. **Given** 设备当前为关闭, **When** 用户打开开关, **Then** 设备收到开启指令，界面开关状态与设备上报一致
3. **Given** 设备当前为开启, **When** 用户关闭开关, **Then** 设备收到关闭指令，界面反映关闭后状态
4. **Given** 设备开启, **When** 用户切换工作模式（无模式/节能/厨房/洗澡/恒温等产品提供的模式）, **Then** 选中模式高亮，设备模式与界面一致
5. **Given** 用户调节设定温度, **When** 确认在允许范围（35–65℃）内的新值, **Then** 设定温度更新到设备，界面显示与设备上报一致
6. **Given** 用户尝试将设定温度调出允许范围, **When** 提交调节, **Then** 不允许下发非法值，界面保持合法温度或夹紧到边界并给出可理解提示

---

### User Story 2 - 故障与燃烧/水流状态感知 (Priority: P1)

用户在首页能感知故障告警；若设计稿首页包含火焰/水流状态，也应一并展示，避免用户误判设备正在加热或有水流动。

**Why this priority**: 燃气热水器涉及安全与故障可读性，故障漏报会造成严重体验与安全风险。

**Independent Test**: 模拟故障位图与火焰/水流状态开关，验证首页提示出现/消失，无需依赖零冷水或设置页。

**Acceptance Scenarios**:

1. **Given** 故障告警为无故障, **When** 查看首页, **Then** 不展示误导性故障主提示
2. **Given** 设备上报一个或多个故障码（如 E0–E8、EH、En、Eb、Ec 等产品定义码）, **When** 查看首页, **Then** 以可读方式展示故障摘要（至少一个用户可理解的故障标识/说明），且不阻断其他已加载状态信息的展示
3. **Given** Figma 首页包含火焰状态与/或水流状态, **When** 对应状态为开或关, **Then** 首页展示与设备上报一致
4. **Given** Figma 首页不包含火焰/水流状态元素, **When** 实现首页, **Then** 不强制增加该展示（延后到后续 feature）

---

### User Story 3 - 从首页进入零冷水占位页 (Priority: P2)

用户在首页看到零冷水入口；点击后进入预留的二级占位页，明确告知完整「设置定时」能力将在后续版本提供，而不是误以为已可配置定时。

**Why this priority**: 固化信息架构与路由，避免 002 返工；但占位页本身不提供定时编辑价值，故次于主控。

**Independent Test**: 仅点击入口进入占位页并返回即可验证，无需真实定时逻辑。

**Acceptance Scenarios**:

1. **Given** 用户在首页, **When** 查看零冷水入口区域, **Then** 入口可见；可展示与零冷水相关的只读摘要（如单次零冷水/常开是否开启的状态摘要），但不提供完整参数调节
2. **Given** 用户点击零冷水入口, **When** 导航完成, **Then** 进入二级占位页，页面说明后续将提供「设置定时」等能力（文案清晰，不伪装为已完成功能）
3. **Given** 用户在占位页, **When** 选择返回, **Then** 回到首页且首页主控状态保持正确

---

### User Story 4 - 设备能力与界面一致 (Priority: P1)

产品物模型（Pro_Key `a3cbezgki7lkl8rr`）中的能力定义与面板识别的能力一致，首页只操作约定的首包能力集，避免「界面有按钮但设备无此能力」或类型/范围错误。

**Why this priority**: 能力模型是所有读写的前提，错误会导致控制失败或危险下发。

**Independent Test**: 对照产品描述文件核对首包能力的类型、读写属性与温度范围，并用虚拟设备验证读写。

**Acceptance Scenarios**:

1. **Given** 产品描述文件已提供, **When** 面板加载设备能力, **Then** 首页使用的能力标识、类型与读写属性与产品定义一致
2. **Given** 首包范围外的能力（增压、变升、浴缸流量、回水温差、点动、保温时长、用气/用水累计等）, **When** 使用首页, **Then** 不提供完整调节入口（可在后续 feature 规划中出现）

---

### Edge Cases

- 设备离线或指令超时：界面给出可理解反馈，不假装已成功改变设备状态
- 出水温度或工作状态短时缺失：显示占位/上次有效值策略需可预期，不崩溃
- 多故障同时存在：至少展示可读摘要，不要求首包做成完整故障手册
- 从占位页深链返回或重复进入：不产生重复页面栈混乱（可预期的返回行为）
- 工作状态为「零冷水加热」时：首页状态文案正确，但不因此解锁 002 的定时编辑

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 面板 MUST 基于产品 Pro_Key `a3cbezgki7lkl8rr` 的物模型对齐设备能力，首页只暴露首包约定能力
- **FR-002**: 用户 MUST 能在首页查看并切换电源开关（`switch`）
- **FR-003**: 用户 MUST 能在首页查看并切换工作模式（`mode`：无模式/节能/厨房/洗澡/恒温等产品枚举）
- **FR-004**: 用户 MUST 能在首页查看并调节设定温度（`temp_set`），合法范围 35–65℃；非法输入 MUST 被拒绝或夹紧到边界并提示
- **FR-005**: 首页 MUST 展示出水温度（`temp_current`）与工作状态（`work_state`）的可读文案
- **FR-006**: 当存在故障告警（`fault`）时，首页 MUST 展示可读故障摘要；无故障时 MUST NOT 显示误导性故障主态
- **FR-007**: 若 Figma 首页包含火焰状态（`flame_state2`）与/或水流状态（`flow_state2`），首页 MUST 按其设计展示；若设计稿无对应元素，首包 MUST NOT 强行加入
- **FR-008**: 首页 MUST 提供零冷水入口；入口可展示只读摘要，MUST NOT 在首包提供完整零冷水参数调节（常开细则、回差、点动、保温时长、完整单次流程配置等）
- **FR-009**: 点击零冷水入口 MUST 进入二级占位页；占位页 MUST 说明「设置定时」等能力将在后续版本提供，并支持返回首页
- **FR-010**: 首页视觉与信息结构 MUST 可追溯到 Figma《国内伊莱克斯零冷水燃气热水器APP-UI方案》（fileKey `vkmMZjILzrheBxPiXO8kF4`）中对应首页节点；设计未定义的元素 MUST NOT 自行发明
- **FR-011**: 所有用户可见文案 MUST 支持产品约定的多语言机制，MUST NOT 在界面硬编码无法切换的中文/英文混排（品牌名、故障码等标识除外）
- **FR-012**: 只读能力 MUST NOT 被首页写成可写操作

### Key Entities

- **设备能力点**: 产品定义的可上报/可下发能力（开关、模式、温度、状态、故障、零冷水相关等），含类型、读写属性、范围/枚举
- **首页主控视图**: 用户第一屏看到的控制与状态集合（首包最小完备集）
- **零冷水入口**: 通往后续「设置定时」的导航入口与可选只读摘要
- **占位二级页**: 预留路由的中间页，承载「后续开放」说明，不编辑定时规则
- **故障摘要**: 由故障位图映射出的用户可读故障标识集合

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 新用户在首次打开面板后 1 分钟内，无需帮助即可完成「查看状态 + 开关或调温」中至少一项主操作
- **SC-002**: 在虚拟设备联调中，首页主控 6 类核心反馈（开关、模式、设定温度、出水温度、工作状态、故障摘要）与设备上报一致率达到 100%（抽样不少于每种状态各 1 次）
- **SC-003**: 设定温度越界操作 100% 不会向设备下发非法值
- **SC-004**: 从首页进入零冷水占位页再返回，往返可在 3 次连续操作内无卡死、无错误页
- **SC-005**: 对照 Figma 首页关键区块（主控、状态、零冷水入口），评审检查清单中「缺失/错位」项为 0（以双方确认的首页节点为准）

## Assumptions

- 首包对照的产品描述文件为 `Debugfile_国内伊莱克斯燃气热水器 ST1 Pro_20260812`（或其等价物模型）
- 用户通过涂鸦智能生活 App 打开单设备面板；首包不要求群组设备特殊 UI
- Figma 首页节点以用户提供的设计文件为准；具体 node 在计划阶段用 Figma 工具精确对齐
- `inlet_temp`（进水温度）、`draught_fan_state`（风机状态）仅当 Figma 首页出现时才纳入展示，否则延后
- 占位页允许简洁文案与基础导航，不要求视觉上等同最终「设置定时」页
- 暗黑模式：若 Figma 未给出暗色稿，首包以亮色稿为准并用主题变量占位，不自行设计暗色视觉

## Out of Scope

- **002**：零冷水「设置定时」完整能力与编辑流程
- **003**：增压、变升、浴缸流量/提醒、回水温差、点动、保温时长、用气/用水累计等设置与专业参数
- **004**：用水/用气曲线统计与体验打磨（若设计包含）
- 完整故障诊断百科、客服工单、固件升级流程定制
- 群组控制专属交互

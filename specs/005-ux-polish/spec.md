# Feature Specification: 体验与视觉打磨

**Feature Branch**: `005-ux-polish`

**Created**: 2026-08-13

**Status**: Implemented (IDE hand-test pending)

**Input**: 005 范围确认 **B**：模式图标 SVG、`ui-diff` 清零、故障与 NavBar/间距一致性；基线 `004-energy-charts` @ `dec73cc`。

**设计权威**: Ardot file `714289030938546`，方案修改页 `55:241`（首页对照 `55:788` / `55:711`；故障条 `55:781`；模式区约 `55:797+`）。工具：Ardot MCP（宪章 Figma 条款的项目既定例外，同 001–004）。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 模式图标对齐设计稿 (Priority: P1)

用户在首页「使用模式」四格中看到与设计稿一致的矢量图标（节能叶、厨宝帽、浴缸、随温感温度计等），选中/未选中态颜色对比清晰；不再依赖「Eco/厨/浴/温」文字占位标记。

**Why this priority**: `ui-diff` 首项残留；模式区是首页高频视觉焦点，文字占位与品牌稿差距最大。

**Independent Test**: 仅替换模式区图标与选中态着色，不改模式切换逻辑即可验收。

**Acceptance Scenarios**:

1. **Given** 设备在线且首页已加载, **When** 查看四模式格, **Then** 每格展示矢量图标（非单字/英文缩写占位），标签文案仍为产品约定中文名（节能/厨宝/浴缸/随温感）
2. **Given** 某模式已选中, **When** 对比未选中格, **Then** 选中格图标与底色对比符合设计稿（深底浅图标 / 浅底蓝图标），切换模式后选中态跟随
3. **Given** 设备离线或控件禁用, **When** 查看模式区, **Then** 图标仍可见且禁用态不误导为可选

---

### User Story 2 - 故障提示可信且不误导 (Priority: P1)

用户在有故障时看到与设计一致的故障提醒条（图标 +「故障提醒：…」+ 处理方案提示）；交互不暗示存在未实现的「故障手册页」。无故障时不出现故障主态。

**Why this priority**: 现横幅带右箭头，易被理解为可进入详情，但 001 明确不做故障手册；打磨需消除误导或给出就地可读反馈。

**Independent Test**: 模拟单故障/多故障/无故障，验证文案、图标与点击行为，无需改模式或定时。

**Acceptance Scenarios**:

1. **Given** 无故障, **When** 查看首页, **Then** 不渲染故障主提示条
2. **Given** 存在一个或多个故障码, **When** 查看首页, **Then** 展示可读故障提醒（至少一个用户可理解的故障说明）与处理方案提示文案，且不阻断其他主控信息
3. **Given** 故障条可见, **When** 用户点击故障条, **Then** 不导航至不存在的故障手册页；若保留可点反馈，则就地展示当前全部故障摘要（如弹层/提示），文案与多语言机制一致
4. **Given** 设计稿故障条含警示图标与箭头, **When** 对照实现, **Then** 图标为矢量或等价图形（非纯「!」字符亦可接受若与稿一致），整体结构对齐 `55:781`

---

### User Story 3 - 跨页 NavBar 与间距一致性 (Priority: P2)

用户从首页进入零冷水定时、定时编辑、能耗报告等子页时，顶栏返回/标题行为一致；首页与子页内容区水平边距、卡片间距在视觉上统一，不再出现明显「一页紧一页松」。

**Why this priority**: 横切打磨；平台保留 SmartUI NavBar（设计稿为纯状态栏全屏）已作为既定约束，目标是一致性而非删 NavBar。

**Independent Test**: 依次打开首页与各已交付子页，对照边距与 NavBar 行为清单，无需改定时配对或图表数据逻辑。

**Acceptance Scenarios**:

1. **Given** 用户在任意已交付子页, **When** 点击顶栏返回, **Then** 回到预期上一页且设备主控状态不因返回而丢失
2. **Given** 首页与子页内容区, **When** 对照水平边距与卡片间距, **Then** 采用同一套间距尺度（与 001 token / 首页内容区一致），无明显不一致项列入未关闭差异
3. **Given** 平台必须使用 SmartUI NavBar, **When** 记录 `ui-diff`, **Then** 「设计稿无 NavBar」项关闭为**已接受平台例外**（附简短理由），不再作为开放缺陷

---

### User Story 4 - ui-diff 清零与文档收口 (Priority: P2)

产品/设计对照 `docs/design/ui-diff.md`：001–004 已交付范围内的开放视觉差异被关闭（已对齐 / 已接受例外），无残留「待做」项指向本 feature 范围内能力。

**Why this priority**: 本 feature 的成功度量即差异清单可关闭；避免口头「差不多」无法验收。

**Independent Test**: 对照更新后的 `ui-diff.md` 与本规格成功标准逐条勾选。

**Acceptance Scenarios**:

1. **Given** US1–US3 已完成, **When** 审阅 `ui-diff.md`, **Then** 原「模式图标文字占位」「故障详情可点无目的地」「瀑布浴/能耗未出（过时）」「NavBar 平台例外」等项均更新为已关闭或已接受，且无过时描述
2. **Given** 对照 Ardot 首页关键帧, **When** 做视觉抽检, **Then** 新增差异若出现须记入文档并分类（修复 / 接受例外）；本 feature 结束时开放项为 0（在 B 范围内）

### Edge Cases

- 多故障同时存在：摘要至少覆盖首个可读说明；若点击展开则列出全部当前码/说明，不要求百科级处理步骤
- 图标资源缺失或加载失败：不得空白到无法识别模式；允许回退到标签文案可读（不得回退为误导性错误色）
- 暗黑/主题变量：颜色 MUST 走既有 CSS 变量；禁止引入米家品牌色或硬编码偏离 token 的主色
- 离线：打磨不改变离线禁用策略；图标与故障条在离线时仍须可读

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 首页四模式格 MUST 使用与 Ardot 模式区一致的矢量图标（节能/厨宝/浴缸/随温感），MUST NOT 再以「Eco/厨/浴/温」文字作为主图标
- **FR-002**: 模式选中/未选中视觉 MUST 对照设计稿区分底色与图标色；模式切换逻辑与 DP 绑定 MUST 保持与 001 一致（本 feature 不改写模式业务规则）
- **FR-003**: 故障横幅在有故障时 MUST 展示可读提醒与处理方案提示；无故障时 MUST NOT 展示故障主态
- **FR-004**: 故障横幅 MUST NOT 导航到未实现的故障手册页；若保留点击，MUST 提供就地全部故障摘要反馈
- **FR-005**: 故障条图形元素（警示图标等）MUST 对齐 Ardot `55:781` 结构意图，并复用 001 主题 token
- **FR-006**: 已交付页面（首页、零冷水定时、定时编辑、能耗报告）的内容水平边距与主要卡片间距 MUST 统一到与首页内容区同一尺度
- **FR-007**: 各子页 NavBar 返回/标题行为 MUST 一致且可用；「设计稿无 NavBar」MUST 在差异文档中关闭为已接受平台例外
- **FR-008**: `docs/design/ui-diff.md` MUST 在本 feature 结束时对 B 范围开放项清零（仅保留已接受例外说明）
- **FR-009**: 视觉与文案 MUST 复用 `docs/design/home-tokens.md` / 既有 CSS 变量与 i18n；MUST NOT 使用米家品牌色
- **FR-010**: MUST NOT 改写 002 零冷水成对定时主路径，MUST NOT 改写 004 能耗 StatCharts/统计请求主路径，除非为满足本规格间距/NavBar 一致性所必需的样式级调整

### Key Entities

- **模式磁贴视觉**: 四模式各自的图标、选中态、标签文案
- **故障摘要展示**: 由故障位图映射的用户可读提醒及可选的就地展开内容
- **页面壳一致性**: NavBar 行为 + 内容区间距尺度
- **UI 差异记录**: `ui-diff.md` 中每条差异的状态（开放 / 已对齐 / 已接受例外）

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 对照 Ardot `55:788`/`55:711`，模式区「文字占位图标」类差异项为 0
- **SC-002**: 故障有/无两种状态下，误导性「可进故障手册」导航为 0；有故障时用户可在 1 次点击内看到当前故障摘要（若保留点击）或明确不可点且无箭头暗示
- **SC-003**: 抽检首页与 ≥3 个子页，内容水平边距不一致项为 0（相对约定尺度）
- **SC-004**: `docs/design/ui-diff.md` 中属于 001–004 已交付范围且属本 feature（B）的开放差异项为 0
- **SC-005**: 回归：模式切换、故障展示、定时列表/编辑主流程、能耗报告图表主流程均可完成（无因本 feature 引入的功能回归）

## Assumptions

- 005 仅做 **B**；**A** 专业参数补齐与 **C** 火焰/水流/进水温度只读展示均不在范围（C 仍需另开规格与设计确认）
- 设计权威继续为 Ardot「方案修改」；宪章 Figma 条款维持项目既定 Ardot 例外
- SmartUI NavBar 保留为平台约束，不追求像素级删除顶栏以匹配设计纯状态栏
- 故障手册/百科页仍不做；就地摘要或去掉可点暗示即可关闭该项
- 003/004 已交付瀑布浴与能耗报告，`ui-diff` 中「首包不出」类过时描述直接关闭并更正
- Token 与品牌色约束沿用 001；中文 commit message
- Skill：`tuya-ray-panel-dev`

## Out of Scope

- 变升 / 浴缸流量 / 回水温差 / 点动 / 保温时长 / 浴缸加热完成提醒等专业参数 UI（选项 A）
- 火焰、水流、进水温度等只读状态挂载（选项 C）
- 新建故障百科/客服工单页
- 重做 002 定时配对逻辑或 004 统计 API/图表数据绑定
- 暗黑模式全套新视觉（除非现有变量已覆盖的小修复）
